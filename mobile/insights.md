## Codebase Patterns
- 2026-09-20: `src/lib/theme` is now the canonical mirror of `design/tokens.md` (colours `tokens.ts`, sizes `metrics.ts`, fonts `typography.ts`; `tokens.test.ts` snapshots every value, so change tokens.md first, then code + that test). Names: `tokens.bg/surface/surfaceStrong/surfaceBorder/divider/textSecondary/textTertiary/…`, `radius`, `layout`, `family`/`size`. `spacing` deliberately keeps the old `xs…xxl` inner-padding scale next to the canonical `screenX/gap/block/section` (tokens.md defines no scale) — `spacing.lg` (16) is card padding, the 20pt screen side margin is `spacing.screenX`. Only the AppText roles `hero/authTitle/h1/cityHero/cardTitle/h2/button/body/small/caption/micro/mono/monoSmall` exist (no `display`/`title`); Plex 400 and Manrope 600 are no longer loaded. `coverColors`, `blurIntensity.tabBar`, `layout.*` and most new colours (`danger`, `warn*`, `tabInactive`, `invertedPill*`, `scrim`, `surfaceStrong`) are defined but not yet consumed by any screen — wiring them is screen work.
- 2026-09-20: A ts-AST rename codemod that only matches `obj.prop` access misses bare identifiers in type/call positions (`typeof FONT_FAMILY`, `Object.values(FONT_FAMILY)`) and string unions (`AppTextColor`) — run `tsc` right after and grep the old names; renames that are not 1:1 (`radii.lg` → `card` vs `cover`, `display` → `h1`/`hero`/`authTitle`) need a per-file table, not a global map.
- 2026-09-21: Trip form (`features/trip-form`): `ModalHeader` always draws "Done" (no way to hide it), so the sheet has its own `FormHeader`; the native compact date picker shows TODAY when empty, so `DatesBlock` renders a plain "empty" button until a date exists and taps apply a fallback (start: today, end: start or today) before mounting `DatePicker` - otherwise the user sees a date that is not in the form (and iOS never fires `onChange` for the day it already shows). The global jest date-picker mock reports its own `value` back, so tests get dates via those fallbacks or edit-mode prefill. An edited trip without dates opens with "No dates yet" set, so shared create/edit tests must un-tick it before touching the pickers. Test the mutations through the real hooks by mocking `@/features/trips/api` (same module id as trips' own `../api`) with a signed-in session, not by mocking the hooks. `TextField` has no `autoFocus`/leading icon, so the destination field is a local `PlaceField` (border accent = directory place picked, deliberately not focus).
- 2026-09-22: The 2026-09-20 note about `mobile/src/mocks/` and `findTrip` is superseded: SPEC-03 removed the mock module, `MOCK_NOW`/`MOCK_USER` and `findTrip`. Trips are real data (`features/trips/api` + TanStack Query), and an unknown / foreign / malformed `tripId` now ends in the one "Trip not found" state instead of falling back to the nearest trip. Guardrails `no-mocks-directory` and `no-direct-clock-outside-clock` keep the mocks and direct clock reads out.
- 2026-09-22: `no-direct-clock-outside-clock`: only an empty-argument `new Date()` and `Date.now(` are clock reads (constructors WITH arguments are legal date math); tests are exempt; `src/lib/clock/` owns the real clock. `src/features/auth/flowState.ts` and `hooks/useResendCountdown.ts` have a narrow, self-tested `ELAPSED_TIME_FILES` allowance for elapsed-time `Date.now()` (moving them onto `lib/clock` is a follow-up).
- 2026-09-22: Guardrail `scan()` applies a rule to ANY path it is given; a rule's scope is applied only in the real-source discovery, so a self-test cannot prove "test files are exempt" by scanning a test path: assert the rule's scope itself. Any `mobile-all` rule also scans `guardrails.test.ts`, so needles and fixtures there must be built from parts or the file trips its own rule. AC-16 (no colour literals outside `lib/theme`) also matches `rgb(` / `hsl(` in comments and template strings, not only hex.
- 2026-09-22: Query hooks must THROW an error carrying `kind` (`TripApiError`) for `shouldRetry` in `lib/query` to retry offline / timeout failures: a queryFn that resolves `{ ok: false }` is a success to TanStack Query and nothing ever retries. `unwrap()` in `features/trips/hooks` is the seam that turns the api result into a throw.
- 2026-09-22: Trips query keys carry no user id, so identity hygiene is `QueryCacheGuard` (mounted in the root layout): it clears the cache when the signed-in identity ENDS or CHANGES, and deliberately NOT on the first `restoring` -> `signedIn` transition, which would orphan an in-flight observer.
- 2026-09-22: `Modal` is a poor host for a menu that immediately pushes a modal route (the native dismiss and the native present race). The details' "..." menu and delete confirmation are an in-tree overlay (`SheetOverlay`: a plain absolute view with a `scrim` backdrop), which also satisfies "not a system Alert" and renders the same on both platforms.
## Tool & Library Notes
- 2026-09-18: Storage libs differ in App Store privacy-manifest impact — AsyncStorage declares only FileTimestamp (C617.1); `react-native-mmkv` uses `UserDefaults` (a required-reason API; verify its installed version ships a `PrivacyInfo.xcprivacy` before adopting); Apple doesn't reliably parse manifests of static CocoaPods, so mirror reasons in `ios.privacyManifests`. Also: iOS Keychain (`expo-secure-store`) data survives app reinstall — clear tokens on fresh install.
- 2026-09-18: A Supabase auth session is larger than `expo-secure-store`'s ~2048-byte value limit — don't store it there directly. Use the LargeSecureStore pattern: AES-256 key in SecureStore, encrypted session in AsyncStorage (backend decision: `docs/decisions/ADR-001-backend-supabase.md`).
- 2026-09-19: i18next typed resources (`CustomTypeOptions.resources: typeof ru`) + `defaultNS` make `i18n.getFixedT(locale)` reject `"ns:key"` strings — bind the namespace instead: `getFixedT(locale, "common")("status.today")`. Plural keys (`_one/_few/_many/_other`) differ between ru and en, so key-parity tests must strip the plural suffix and separately assert each locale defines exactly `new Intl.PluralRules(locale).resolvedOptions().pluralCategories`. `createInstance().init({ initAsync: false })` with bundled resources initialises synchronously (no first-render flash of keys). Jest (Node ICU) proves i18next plural/`Intl.DateTimeFormat` logic only — it says nothing about Hermes' Intl coverage (PLAN-01 R-3 stays a device check).
- 2026-09-19: Privacy-manifest audit under pnpm: `find node_modules` misses most manifests (nested, symlinked, one copy per peer resolution) — walk `node_modules/.pnpm` with real paths and dedupe by package@version + content hash. The linked-pod list comes from `npx expo-modules-autolinking resolve --platform apple --json` (from `mobile/`, no dev server). `expo-dev-launcher`/`expo-dev-menu` touch `UserDefaults` with no manifest but are `debugOnly` (absent from Release builds) — not a stop-signal. Beyond the C617.1 AsyncStorage expectation, the actual SDK 57 union also needs UserDefaults CA92.1, SystemBootTime 35F9.1, DiskSpace E174.1/85F4.1 and FileTimestamp 0A2A.1/3B52.1 (expo-file-system, a transitive `expo` dep). Details: `docs/release/privacy-manifest-audit.md`.
- 2026-09-19: `expo-blur` (SDK 57) on Android only blurs when given a `blurTarget` ref to a `<BlurTargetView>` wrapping the content behind it; `blurMethod="dimezisBlurView*"` without one warns on every mount and falls back to `none`, and `experimentalBlurMethod` is deprecated (warns too). So `platform/blur.android.ts` requests `blurMethod: "none"` (translucent view) until a screen-level BlurTargetView exists; the glass look comes from token fill + border.
- 2026-09-19: `ThemeProvider` reads AsyncStorage asynchronously, so a sync `render()` yields "update not wrapped in act(...)" console errors when its read resolves. `renderWithProviders` is therefore async (`await renderWithProviders(...)`): it applies the preference like a user pick and `waitFor`s `isReady`. Default preference is "dark" (not the stored value) so the AsyncStorage mock's leftover value can't leak between tests.
- 2026-09-19: Keyboard-safe `Screen` without `Platform.OS`: `ScrollView` with `automaticallyAdjustKeyboardInsets` (iOS-only prop, ignored on Android, where the window resizes) + `keyboardShouldPersistTaps="handled"`. `KeyboardAvoidingView behavior="padding"` would double-count on Android and force a platform fork. To assert "accessibilityLabel is required" without `@ts-expect-error` (banned), assign a tuple of `IsRequired<Props,"accessibilityLabel">` types to `true`s.
- 2026-09-19: RNTL `getByRole` only matches accessible elements, so a non-accessible container `accessibilityRole="radiogroup"` is invisible to it (and making it `accessible` would make VoiceOver swallow its radios) — query the group by `getByLabelText` and the options by `getByRole("radio", { name, checked })`. Theme has no cover palette, so trip-cover placeholders vary `tokens.accent` opacity over `tokens.pill` instead of inventing colours in a feature.
- 2026-09-19: RNTL `userEvent.press` on a RN `<Switch>` does not flip it (the native `onValueChange` never fires) — drive it with `fireEvent(toggle, "valueChange", next)` and assert with `toBeChecked()` on `getByRole("switch")`. When a route param is spliced into an href (`/trips/${id}/flights/new`), `encodeURIComponent` it: a hostile id like `../../etc` then stays one path segment instead of rewriting the route.
- 2026-09-19: expo-router treats EVERY `.tsx`/`.ts` under `app/` as a route — its `require.context` regex has no `__tests__`/`.test.` exclusion (and `renderRouter`'s directory ponyfill scans all `.[tj]sx?`) — so tests must live outside `app/` (`mobile/__tests__/`); `routes.contract.test.ts` fails on any non-route file in `app/`. `renderRouter("./app", { initialUrl })` from `expo-router/testing-library` works in expo-router 57 and drives the real layouts, but: (1) the project `jest.config.js` `transformIgnorePatterns` must include `standard-navigation` (ESM-only dep; jest-expo's preset lists it, our override dropped it); (2) `expect(screen).toHavePathname` exists at runtime but has no typings — assert via the `getPathname()` of the render result; (3) JS bottom-tab buttons render as `role="button"` inside a non-accessible `role="tablist"` (query `getByRole("button", { name, selected })`, not `"tab"`); (4) `getRouterState()` wraps the app in a synthetic `__root` route — the app stack is `routes[0].state.routes`.
- 2026-09-19: `typedRoutes` types (`.expo/types`) are generated only by the dev server (`expo start`), NOT by `expo export`; `expo export --platform ios` is still a cheap no-simulator proof that the whole route tree bundles. `@types/node` is not a `mobile` dependency (tsconfig `types: ["jest"]`), so tests that read the filesystem type `jest.requireActual("node:fs")` locally instead.
- 2026-09-20: Mock content lives in ONE module, `mobile/src/mocks/` (trips + flights + hotels + user, all rendered against the fixed `MOCK_NOW`); features import it, so swapping in the real `api/` layer touches one seam. Flight times are stored as UTC instants plus the departure airport's IANA `timeZone` and rendered with `formatTime(locale, date, timeZone)` — the default `timeZone` of the i18n formatters is UTC, so a card that forgets to pass it shows a wrong wall-clock time. In tests, `Intl.DateTimeFormat#formatRange` output contains thin/no-break spaces around the en dash (`"Sep 25 – Oct 1"` is NOT `===` a typed string); `getByText` normalises them, but `toEqual` on an `accessibilityLabel` does not — `.replace(/\s/g, " ")` first. Unknown trip ids fall back to the nearest trip (`findTrip`), keeping the "arbitrary tripId never breaks S7" AC.
- 2026-09-20: Icons go through `src/components/Icon` (semantic name -> glyph in `components/icons.ts`, size = `iconSize` token, colour = theme token key; decorative, so it is hidden from the a11y tree — the parent control owns the label and RNTL needs `includeHiddenElements: true` to find it). `@expo/vector-icons` is font-based (needs only the already-installed `expo-font`, no `react-native-svg`, no dev-client rebuild). Feather has NO plane, bed or car (nor a suitcase — `briefcase` stands in), so `plane`/`bed`/`car` come from the Ionicons `-outline` set of the same package; `Icon.test.tsx` pins that exactly those three are non-Feather. Ionicons outlines are slightly thinner than Feather's 2px stroke — swap them if a designer objects. Don't draw arrows/plus/minus as text (`→`, `+`, `−`): a route like `WAW → LIS` is now two mono `Text`s around an `Icon`, and its spoken form is the i18n key `tripDetail:flight.route`, so tests read it with `getByLabelText`, not `getByText("WAW → LIS")`.
- 2026-09-21: expo-router `Stack.Protected` (57.0.22) appends every route file the layout does NOT declare as UNGUARDED, so a signed-out user could deep-link into it. Every guarded route (including `trips/[tripId]/index`) must have a `<Stack.Screen name=…>` inside a `Stack.Protected` in `app/_layout.tsx`; `__tests__/navigation.test.tsx` asserts each one, so a new route file without a declaration fails there.
- 2026-09-21: Password recovery is a two-step flow that fights the auth gating: `verifyOtp({type:"recovery"})` consumes the code AND opens a session BEFORE `updateUser({password})`, so the session provider would see "signed in" and bounce `/reset-password` to `/trips`. `useSession().holdGating()` suspends the redirect while S10b is open; an abandoned reset after an accepted code must `signOut`, or the user is left signed in without ever choosing a password (`ResetPasswordScreen.tsx`).
- 2026-09-21: `supabase.auth.getSession()` OFFLINE with an expired access token tries a refresh and returns `AuthRetryableFetchError` with a null session — the cold start would show onboarding (AC-9). Session restore falls back to the locally stored session (`readStoredSessionUser` in `lib/storage`) on retryable network errors. Likewise `auth.signOut()` leaves the local session in place on a network error, so `authApi` retries with `{ scope: "local" }` (never touches the server).
- 2026-09-21: expo-router 57 `router.navigate("/sign-in")` from S3 PUSHES a duplicate S2 instead of popping back to the one below it, so the S3 → S2 email prefill (`features/auth/flowState.ts`) is kept until explicitly cleared and delivered to listeners, not consumed on first read — the duplicate S2 would otherwise render empty.
- 2026-09-22: `process.env.TZ` set inside a jest test does not reach `Date` / `Intl` (Node reads it at startup). Simulate a device time zone by wrapping `Intl.DateTimeFormat` so an unspecified `timeZone` defaults to the target zone (`lib/i18n/__tests__/format.test.ts` does this with `jest.spyOn(Intl, "DateTimeFormat")`).
- 2026-09-22: `FlatList`/`VirtualizedList` re-plans its render window on a ~50 ms timer after mount and after each data change, so list tests flake with act warnings. Wait it out: `await act(async () => { await new Promise((r) => setTimeout(r, 60)); })` after render, and until `queryClient.isFetching() === 0`.
- 2026-09-22: The library's default-export `DateTimePicker` on Android opens its dialog on MOUNT and renders `null`, so a form that always mounts it would pop a dialog immediately. `platform/datePicker` therefore renders a themed trigger and calls the imperative `DateTimePickerAndroid.open` on press (a legal platform fork, it lives in `platform/`). On iOS the compact control shows today when the value is null; the form's empty-button handling is in the trip-form entry above.
- 2026-09-22: postgrest-js 2.x does NOT throw on a failed fetch: it resolves `{ error: { message: "AbortError: ...", code: "" }, status: 0 }` (an abort or timeout looks like this too). Error classifiers (`features/trips/api/errors.ts`) must read both the message and the status; one that only checks `error.code` sees an empty string and reports `unknown` for every offline case.
- 2026-09-22: `QueryClient.clear()` does not stop the 5-minute gc timer of finished MUTATIONS, so a jest file that runs mutations hangs unless each test unmounts, destroys the mutations (`getMutationCache().getAll()` -> `destroy()`) and only then clears the client (`useTripMutations.test.tsx`). The full mobile run still prints one "worker failed to exit gracefully" line.
- 2026-09-22: macOS has no `timeout` command (use the tool's timeout or a background run). A full jest run of `navigation.test.tsx` without a `QueryClient` took ~19 minutes before `QueryProvider` was in the layout; with it the whole mobile suite (919 tests) runs in ~30 s.
## Recurring Errors & Fixes
- 2026-09-22: Jest modern fake timers (`jest.useFakeTimers()`) tie `Date`/`Date.now()` to the
  virtual clock, so calling `jest.setSystemTime(t)` AND THEN `jest.advanceTimersByTime(ms)`
  double-moves time (the advance is added on top of the manually set instant, not from where the
  timers last stood) — a test asserting an exact elapsed-time boundary (e.g. "the minute-interval
  timer fires at exactly 60s, not 59s") must pick ONE mechanism: either drive time purely with
  `advanceTimersByTime` from mount (timers and `new Date()` stay in lockstep), or use
  `setSystemTime` alone with no timer advance (for "an event fires and reads the clock instantly,
  no timer involved" cases). Mixing both in the same assertion produces a silently-wrong expected
  value (`mobile/src/lib/clock/__tests__/useNow.test.tsx`).
- 2026-09-22: An ALREADY-INSTALLED dev-client does not reconnect to a freshly started `npx expo start` — it keeps rendering whatever JS it last successfully loaded (from before `src/mocks/` was deleted, in this case), and never makes a bundle request to the new Metro at all (nothing in the Metro log). `mobile/.env` pointing at the right Supabase URL/key is irrelevant here — the app is not even running current JS. Symptom: a brand-new signed-up account shows old mock trips/history. Starting Metro is NOT enough to pick up code changes on a device/simulator whose dev-client was built before those changes; a second `npx expo start` on the same port just refuses (asks to use another port) instead of "waking up" the stale one. Fix: `npx expo run:ios --device "<name>"` to rebuild and reinstall the dev-client, which relaunches it pointed at the current Metro (confirmed by an "iOS Bundled … (N modules)" line appearing in the Metro log right after).

- 2026-09-21: The session codec must not use aes-js `utils.utf8`: it corrupts 4-byte characters (an emoji in `display_name` broke the stored session on the next read). `sessionSecureStorage.ts` goes through `encodeURIComponent`/`decodeURIComponent` instead; the test pins an emoji round trip.
- 2026-09-21: `@/lib/supabase` throws `ConfigError` at IMPORT time when `EXPO_PUBLIC_SUPABASE_*` are unset (AC-47), so any test that touches it crashes at load: `jest.setup.ts` sets fake public defaults. To test the unset case, `delete process.env.X` — `process.env.X = undefined` stores the string `"undefined"` (a "valid" config).
- 2026-09-21: jest gotchas found in the auth tests: `renderRouter` runs on fake timers (flush with `await act(async () => {})`, not a `setTimeout` sleep); `AppState.currentState` on the RN jest mock is a plain data property (use `Object.defineProperty`); RNTL `rerender` of `renderWithProviders` drops the providers (write a stateful harness instead); `AccessibilityInfo.announceForAccessibility` is one shared `jest.fn` (`mockClear` per test); jest collects EVERY file under `__tests__/`, so a helper there needs a tiny test or must live elsewhere (`features/auth/__tests__/testKit.tsx` carries one tiny test for this reason); `renderRouter("./app")` also works from tests inside `src/`. A `TextField` with an error exposes the composite label "Label, error text", so `getByLabelText` must match that form.
- 2026-09-21: `npx expo install expo-secure-store` prints an optional `plugins: ["expo-secure-store"]` hint for a dynamic `app.config.ts`; it only adds a Face ID usage string, and this project forbids new `NS*UsageDescription` (PLAN-02 stop-list 9) — deliberately NOT added; the plain SecureStore calls need no plugin.
- 2026-09-19: `app.config.ts` can't `import "./sibling"` a `.ts` file — Expo CLI transpiles only the config file itself, then plain Node resolves imports (`Cannot find module './app.constants'` from `expo config`). Extensionless static imports fail; `import "./x.ts"` fails `tsc` (needs `allowImportingTsExtensions`). What works with no tsconfig change: `require("./x.ts") as typeof import("./x")` (Node >=22.18 strips types). Jest passes either way, so only `npx expo config` catches it.
- 2026-09-19: In Jest 29, `jest.restoreAllMocks()` does NOT reset `jest.spyOn(AsyncStorage, "getItem").mockRejectedValue(...)` — the async-storage jest mock's methods are already `jest.fn`s, so the rejecting implementation leaks into later tests in the file. Use `mockRejectedValueOnce` to simulate failures against the AsyncStorage mock.
- 2026-09-19: `npx expo run:ios` on the iOS 27 simulator (Xcode 27, Expo SDK 57, iPhone 17) builds and installs fine, then the app dies at launch with SIGTRAP in `___UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption` — Metro is never reached, so it looks like a JS problem but isn't. Suspected cause (NOT verified by a fix): iOS 27 requires UIScene lifecycle adoption and the CNG-generated `AppDelegate` doesn't have it. Don't hand-edit `mobile/ios/` (CNG); check for an Expo SDK 57 patch / config plugin, or use an iOS <=26 simulator or device. Only iOS 27 runtimes were installed when this was hit, so nothing that needs a running app (Maestro flows, manual checklist) could be run.
- 2026-09-19: pnpm 11 breaks a fresh Expo SDK 57 install two ways, both fixed only in the ROOT `pnpm-workspace.yaml`: `ERR_PNPM_IGNORED_BUILDS` (dependency build scripts are blocked by default → `allowBuilds: { '@parcel/watcher': false, unrs-resolver: false }`, neither needs a build) and `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION` (packages published <24 h ago are rejected → `minimumReleaseAgeExclude` listing the exact `pkg@version`s). The second is temporary: delete it once those versions are a day old. Also TypeScript 6 no longer auto-includes `@types/*`, so `mobile/tsconfig.json` needs `"types": ["jest"]` (add `node` if a step reads the filesystem).
- 2026-09-19: Follow-up on the iOS 27 launch crash (verified by diffing templates): the scene-lifecycle runtime code is ALREADY in installed `expo@57.0.24` (`ios/AppDelegates/ExpoAppSceneDelegate.swift`, `ExpoReactNativeFactoryProvider.swift`), but the `expo-template-bare-minimum@sdk-57` (57.0.26, what `expo prebuild`/`run:ios` generates from) does not use it; only the SDK 58 template (`@next`, 58.0.3) does. The generated project needs three changes: `AppDelegate: ExpoAppDelegate, ExpoReactNativeFactoryProvider` without creating the window / calling `startReactNative`; a new `SceneDelegate.swift` (`@objc(SceneDelegate) class SceneDelegate: ExpoAppSceneDelegate {}`) added to the Xcode target; and `UIApplicationSceneManifest` in `Info.plist` (`UISceneDelegateClassName = $(PRODUCT_MODULE_NAME).SceneDelegate`, multiple scenes off). Since `mobile/ios/` is generated, the CNG-safe fix is a local config plugin applying those three edits — not hand-editing `ios/` (lost on `prebuild --clean`). Not implemented yet.
- 2026-09-19: FIXED and verified on the iOS 27 simulator (iPhone 17, Xcode 27): `mobile/plugins/withIosSceneLifecycle.js` (registered as `"./plugins/withIosSceneLifecycle"` in `app.config.ts`) applies the three scene-lifecycle edits during prebuild via `withAppDelegate` + `withInfoPlist`; `SceneDelegate` is appended to the generated `AppDelegate.swift` so no `.pbxproj` edit is needed, and the existing AppDelegate Linking overrides are kept (ExpoAppSceneDelegate forwards URL/activity events to them). After `expo prebuild --clean` + `expo run:ios` the app launches and shows onboarding instead of SIGTRAP. `patchAppDelegate` throws if the template shape changes (a silent no-op would only resurface as the iOS 27 crash); covered by `__tests__/ios-scene-plugin.test.ts`. Delete the plugin once the SDK 57 template (or SDK 58) adopts scenes natively.
- 2026-09-19: Running Metro (`expo run:ios` / `expo start`) generates `.expo/types/router.d.ts`, after which `tsc` checks routes strictly: template-literal hrefs built from a variable prefix (e.g. ``router.push(`${base}/cars/new`)`` in `TripDetailScreen.tsx`) stop compiling (5 errors) even though the same code typechecked in a clean clone before. Use `{ pathname: "/trips/[tripId]/cars/new", params: { tripId } }` for dynamic routes. Metro also rewrites `mobile/.gitignore` (adds `expo-env.d.ts`) and touches `expo-env.d.ts` — `git checkout --` both before committing (the file is deliberately tracked).
- 2026-09-19: With object hrefs (`router.push({ pathname: "/trips/[tripId]/flights/new", params: { tripId } })`) expo-router itself `encodeURIComponent`s dynamic-segment params (`link/href.js` `createQualifiedPathname`/`encodeParam`), so pass the RAW id — do NOT pre-encode (that would double-encode) — and a hostile id like `../../etc` still stays one segment; this supersedes the manual-`encodeURIComponent` advice in the RNTL/Switch entry above, which only applies to hand-built template-literal hrefs. In `renderRouter` tests `getPathname()` returns the DECODED path (`/trips/../../etc/flights/new`), so it can't tell "one encoded segment" from "extra segments": assert the top route's `name` (`trips/[tripId]/flights/new`) and `params.tripId` from `getRouterState()` instead.
- 2026-09-21: Follow-up to the offline `getSession()` entry: `supabase.auth.onAuthStateChange` ALSO fires `('INITIAL_SESSION', null)` whenever supabase-js's own session load errors (`auth-js` `_emitInitialSession`, `GoTrueClient.js` ~3657) — that includes the offline refresh failure. A provider that treats the first event as the answer settles `signedOut` before the `getSession()` fallback (stored user) can run, so AC-9 silently fails while a hand-rolled fake client that never emits `INITIAL_SESSION` passes every unit test. `SessionProvider` ignores a null `INITIAL_SESSION` and lets the `getSession()` result decide; the test mock emits `INITIAL_SESSION(null)` from a microtask on subscribe like the real client. Any test double of `onAuthStateChange` should do the same.
- 2026-09-22: `Date.UTC(2026, 1, 30)` silently rolls over to March 2, so a "YYYY-MM-DD" parser that only checks the pattern accepts `2026-02-30`. Round-trip the components (`getUTCFullYear/Month/Date` must equal the input), as `lib/i18n/format.ts` does; `shared` `isCalendarDate` checks days-in-month explicitly.
- 2026-09-22: Any screen that gains `useQuery` breaks every real-route test until `QueryProvider` is in the layout under test, and real-route tests that reach `/trips` must mock `@/features/trips/api`. `renderApp`'s wait on a `-screen$` testID resolves on a LOADING state (the screen shell is there before the data): wait separately for the content you assert on.
- 2026-09-22: The generated `.expo/types/router.d.ts` goes STALE the moment a route file is added: in a checkout where Metro ever ran, `pnpm typecheck` then fails on every href to the new route (4 errors for `/trips/[tripId]/edit`) although the code is correct, while a fresh clone or a git worktree (no generated file) typechecks clean — so implementers in worktrees report green and the red only shows up in the main checkout. Fix: run `npx expo start` once to regenerate (or delete the gitignored file), then `git checkout --` the `.gitignore`/`expo-env.d.ts` Metro rewrites.
