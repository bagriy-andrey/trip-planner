## Tool & Library Notes
- 2026-09-18: Storage libs differ in App Store privacy-manifest impact — AsyncStorage declares only FileTimestamp (C617.1); `react-native-mmkv` uses `UserDefaults` (a required-reason API; verify its installed version ships a `PrivacyInfo.xcprivacy` before adopting); Apple doesn't reliably parse manifests of static CocoaPods, so mirror reasons in `ios.privacyManifests`. Also: iOS Keychain (`expo-secure-store`) data survives app reinstall — clear tokens on fresh install.
- 2026-09-18: A Supabase auth session is larger than `expo-secure-store`'s ~2048-byte value limit — don't store it there directly. Use the LargeSecureStore pattern: AES-256 key in SecureStore, encrypted session in AsyncStorage (backend decision: `docs/decisions/ADR-001-backend-supabase.md`).
- 2026-09-19: i18next typed resources (`CustomTypeOptions.resources: typeof ru`) + `defaultNS` make `i18n.getFixedT(locale)` reject `"ns:key"` strings — bind the namespace instead: `getFixedT(locale, "common")("status.today")`. Plural keys (`_one/_few/_many/_other`) differ between ru and en, so key-parity tests must strip the plural suffix and separately assert each locale defines exactly `new Intl.PluralRules(locale).resolvedOptions().pluralCategories`. `createInstance().init({ initAsync: false })` with bundled resources initialises synchronously (no first-render flash of keys). Jest (Node ICU) proves i18next plural/`Intl.DateTimeFormat` logic only — it says nothing about Hermes' Intl coverage (PLAN-01 R-3 stays a device check).
- 2026-09-19: Privacy-manifest audit under pnpm: `find node_modules` misses most manifests (nested, symlinked, one copy per peer resolution) — walk `node_modules/.pnpm` with real paths and dedupe by package@version + content hash. The linked-pod list comes from `npx expo-modules-autolinking resolve --platform apple --json` (from `mobile/`, no dev server). `expo-dev-launcher`/`expo-dev-menu` touch `UserDefaults` with no manifest but are `debugOnly` (absent from Release builds) — not a stop-signal. Beyond the C617.1 AsyncStorage expectation, the actual SDK 57 union also needs UserDefaults CA92.1, SystemBootTime 35F9.1, DiskSpace E174.1/85F4.1 and FileTimestamp 0A2A.1/3B52.1 (expo-file-system, a transitive `expo` dep). Details: `docs/release/privacy-manifest-audit.md`.
- 2026-09-19: `expo-blur` (SDK 57) on Android only blurs when given a `blurTarget` ref to a `<BlurTargetView>` wrapping the content behind it; `blurMethod="dimezisBlurView*"` without one warns on every mount and falls back to `none`, and `experimentalBlurMethod` is deprecated (warns too). So `platform/blur.android.ts` requests `blurMethod: "none"` (translucent view) until a screen-level BlurTargetView exists; the glass look comes from token fill + border.
- 2026-09-19: `ThemeProvider` reads AsyncStorage asynchronously, so a sync `render()` yields "update not wrapped in act(...)" console errors when its read resolves. `renderWithProviders` is therefore async (`await renderWithProviders(...)`): it applies the preference like a user pick and `waitFor`s `isReady`. Default preference is "dark" (not the stored value) so the AsyncStorage mock's leftover value can't leak between tests.
- 2026-09-19: Keyboard-safe `Screen` without `Platform.OS`: `ScrollView` with `automaticallyAdjustKeyboardInsets` (iOS-only prop, ignored on Android, where the window resizes) + `keyboardShouldPersistTaps="handled"`. `KeyboardAvoidingView behavior="padding"` would double-count on Android and force a platform fork. To assert "accessibilityLabel is required" without `@ts-expect-error` (banned), assign a tuple of `IsRequired<Props,"accessibilityLabel">` types to `true`s.
- 2026-09-19: RNTL `getByRole` only matches accessible elements, so a non-accessible container `accessibilityRole="radiogroup"` is invisible to it (and making it `accessible` would make VoiceOver swallow its radios) — query the group by `getByLabelText` and the options by `getByRole("radio", { name, checked })`. Theme has no cover palette, so trip-cover placeholders vary `tokens.accent` opacity over `tokens.pill` instead of inventing colours in a feature.
- 2026-09-19: RNTL `userEvent.press` on a RN `<Switch>` does not flip it (the native `onValueChange` never fires) — drive it with `fireEvent(toggle, "valueChange", next)` and assert with `toBeChecked()` on `getByRole("switch")`. When a route param is spliced into an href (`/trips/${id}/flights/new`), `encodeURIComponent` it: a hostile id like `../../etc` then stays one path segment instead of rewriting the route.
## Recurring Errors & Fixes
- 2026-09-19: `app.config.ts` can't `import "./sibling"` a `.ts` file — Expo CLI transpiles only the config file itself, then plain Node resolves imports (`Cannot find module './app.constants'` from `expo config`). Extensionless static imports fail; `import "./x.ts"` fails `tsc` (needs `allowImportingTsExtensions`). What works with no tsconfig change: `require("./x.ts") as typeof import("./x")` (Node >=22.18 strips types). Jest passes either way, so only `npx expo config` catches it.
- 2026-09-19: In Jest 29, `jest.restoreAllMocks()` does NOT reset `jest.spyOn(AsyncStorage, "getItem").mockRejectedValue(...)` — the async-storage jest mock's methods are already `jest.fn`s, so the rejecting implementation leaks into later tests in the file. Use `mockRejectedValueOnce` to simulate failures against the AsyncStorage mock.
