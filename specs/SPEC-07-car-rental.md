## Проблема и зачем

После SPEC-05 блок «Аренда авто» на S7 остаётся пустой рамкой, а `/trips/[tripId]/cars/new` — заглушкой
из четырёх неинтерактивных полей (`booking-form`, вариант `car`): ничего не валидируется и не сохраняется.

Ценность брони авто в «кошельке» — то, что нужно на стойке проката: номер брони, время и место получения,
адрес и телефон офиса, страховка и топливо, что оплачено, и как дойти до офиса. Поля выведены из реального
ваучера (Centauro, Порту, 19–27.08.2026). Отсюда три части: настоящая форма, карточка на S7 и новый экран
«Просмотр брони» — то, что открывают на стойке, а не форма правки.

Макет из Claude Design **расходится** с `design/screens/add-car.md` (убран «Водитель», компания
необязательна, добавлены ссылка на карты, телефон, оплата, залог, экран просмотра). Спек фиксирует
макет как итог; `add-car.md` обновляется под него.

## Goals / Non-goals

**Goals**
1. Аренды хранятся в `trip_cars` с RLS через поездку (приём `trip_hotels`).
2. Полный CRUD одной аренды: создание, просмотр, правка, удаление с подтверждением; в поездке их может быть несколько.
3. Форма заполняется руками, без сети, кроме самого сохранения.
4. Получение и возврат — календарные даты места + обязательные местные времена (как у отеля после поправки 2026-09-24).
5. Стоимость и залог — числа в валюте **записи**; домашняя валюта профиля лишь умолчание для НОВОЙ записи (SPEC-06).
6. «Ссылка на карты» — та же проверка `parseMapsUrl` и то же поведение, что у отеля.
7. Блок «Аренда авто» на S7 показывает карточки; тап открывает просмотр брони.
8. Просмотр брони: копирование номера, «Маршрут» (ссылка на карты), «Позвонить» (`tel:`).
9. Предупреждение «возврат авто позже вылета обратного рейса» (из `add-car.md`) — чистая функция в `shared/`.

**Non-goals**
- Поиск прокатов, цены, сравнение, подтягивание из Booking/ваучера (импорт: `source` пишется только `manual`).
- Часы работы офиса; водитель (имя как в правах) — убран макетом.
- Конвертация валют и итоги; конфликты «авто ↔ отель», «получение ↔ прилёт» (кроме одного предупреждения выше).
- Превью карты, раскрытие коротких ссылок, фото, вложения, шаринг, Apple Wallet.
- Единообразие «тап по карточке» и календаря для отеля и авто — отдельная задача (см. Follow-ups).

## User stories
- **US-1.** Жму «+» у блока «Аренда авто», ввожу номер брони и место получения — даты уже предзаполнены датами поездки.
- **US-2.** На стойке открываю бронь: крупный номер, кнопка «Копировать», время и место получения.
- **US-3.** Не знаю дорогу — жму «Маршрут», открывается Google Maps; или «Позвонить» в офис.
- **US-4.** Возвращаю авто в другом месте — выключаю «Возврат там же» и пишу место возврата.
- **US-5.** Отменил аренду — удаляю запись с подтверждением.
- **US-6.** Вернуть авто надо после вылета обратного рейса — вижу предупреждение под временами.

## Модель данных (контракт, не SQL)

Одна новая таблица `trip_cars`. Точный DDL — дело Implementation Plan.

| Поле | Смысл | Обязательность |
|---|---|---|
| `id` | UUID, сервер | PK |
| `trip_id` | FK `trips` `ON DELETE CASCADE`; через него выводится владение | not null |
| `source` | `manual` \| `imported_pending` \| `imported_confirmed`, по умолчанию `manual` | not null |
| `booking_ref` | Номер брони, 1…32 после trim | not null |
| `company` | Компания, до 120 | nullable |
| `pickup_place` | Место получения, до 300 | not null |
| `pickup_date` / `return_date` | Календарные даты места (`date`) | not null |
| `pickup_time` / `return_time` | Местное время (`time`) | not null |
| `return_same_place` | Возврат там же, по умолчанию `true` | not null |
| `return_place` | Место возврата, до 300; обязательно ⇔ `return_same_place = false` | nullable |
| `maps_url` | Ссылка Google Maps, нормализованная, до 2048 | nullable |
| `address` | Адрес офиса, многострочный, до 300 | nullable |
| `phone` | Телефон офиса, до 32 символов; после удаления пробелов, `-`, `(`, `)` — необязательный ведущий `+` и 3…15 цифр | nullable |
| `car_class` | Модель или класс, одной строкой, до 120 | nullable |
| `insurance` | `none` \| `excess` \| `full` | nullable (по умолчанию не выбрано) |
| `fuel_policy` | `full_full` \| `full_empty` \| `other` | nullable |
| `cost_amount` | Стоимость: неотрицательное, до 2 знаков, до 12 цифр | nullable |
| `cost_currency` | ISO 4217, 3 заглавные | nullable |
| `payment_status` | `paid` \| `on_site` | nullable |
| `extra_driver` | Доп. водитель, по умолчанию `false` | not null |
| `deposit_amount` | Залог на карте: как `cost_amount`, в валюте записи (`cost_currency`) | nullable |
| `notes` | Заметки, до 1000 | nullable |
| `created_at` / `updated_at` | Служебные; `updated_at` — триггер `set_updated_at` | not null |

Инварианты: `return_date >= pickup_date`; `return_date - pickup_date <= 365`; при равных датах
`return_time > pickup_time`; `return_place is not null` ⇔ `return_same_place = false`; валюта обязательна,
если заполнена стоимость или залог, и наоборот — валюта без стоимости и залога недопустима.

## Acceptance criteria (EARS)

### Хранение, владение и RLS
- **AC-1.** The system **shall** хранить аренды в `trip_cars`, созданной миграцией `supabase/migrations/`.
  *Verify: manual (`supabase db reset` локально) + db.*
- **AC-2.** The system **shall** держать RLS на `trip_cars` с политиками `select/insert/update/delete`, допускающими
  строку только когда её `trip_id` указывает на поездку текущего пользователя; `update` проверяет ownership и в
  `using`, и в `with check`. *Verify: db (pgTAP: владелец / другой / anon на каждую операцию).*
- **AC-3.** IF пользователь читает, меняет или удаляет аренду чужой поездки, THEN the system **shall** вести себя так,
  будто строки нет. *Verify: db.*
- **AC-4.** IF вставка идёт с `trip_id` чужой или несуществующей поездки, ИЛИ update переносит аренду в чужую поездку,
  THEN the system **shall** отклонить операцию. *Verify: db.*
- **AC-5.** WHEN удаляется поездка или пользователь, the system **shall** удалить её аренды каскадом. *Verify: db.*
- **AC-6.** The system **shall** проверять инварианты CHECK-ограничениями БД: длины и форматы полей, порядок дат,
  365 суток, кросс-время в один день, значения enum, пара `return_same_place`/`return_place`, связь валюты со
  стоимостью и залогом, формат валюты. *Verify: db (по одному падающему insert на ограничение).*
- **AC-7.** The system **shall** регенерировать `shared/src/db/database.types.ts` после миграции.
  *Verify: manual + typecheck.*

### Форма: оболочка, поля, предзаполнение
- **AC-8.** The system **shall** оформить форму как формы SPEC-04/05: модальная шторка, шапка с крестиком (голосом
  «Отмена») и заголовком «Аренда авто» по центру, **без** «Готово»; прокручиваемое тело; нижняя панель с «Сохранить»
  (пилюля 52); «Сохранить и добавить следующий» нет. *Verify: unit.*
- **AC-9.** The system **shall** показывать поля в порядке HANDOFF: Номер брони (моно), Компания; группа «Получение и
  возврат»: Место получения, Даты, Время получения, Время возврата (ряд из двух колонок), «Возврат там же», Место
  возврата (только при выключенном переключателе, 2 строки); группа «Офис»: Ссылка на карты, Адрес, Телефон (клавиатура
  `tel`); группа «Машина и условия»: Модель или класс, Страховка, Топливо; группа «Оплата»: Стоимость + валюта, Статус
  оплаты; свёрнутый блок «Ещё» (подпись «Доп. водитель, залог, заметки»): Доп. водитель, Залог на карте, Заметки.
  Заголовки групп — `h2`. *Verify: unit (RNTL) + manual против макета.*
- **AC-10.** The system **shall** оформить «Страховка» (Нет / С франшизой / Без франшизы), «Топливо» (Бак в бак / Сдать
  пустым / Другое) и «Статус оплаты» (Оплачено / Оплата на месте) как сегмент-контролы с `accessibilityRole="radiogroup"`
  и вариантами `radio` с `checked`; по умолчанию ничего не выбрано; повторный тап по выбранному снимает выбор (значение снова `null`, иначе ошибочный выбор не отменить). Выбранный — `accent`/`onAccent`, мин. высота 40,
  зона нажатия ≥44pt. *Verify: unit.*
- **AC-11.** WHEN форма открыта на создание, the system **shall** предзаполнить диапазон дат датами поездки (при
  создании начало не раньше сегодня, поведение как у отеля, AC-66 SPEC-05); времена пусты; «Возврат там же» включён;
  валюта — домашняя валюта профиля, если она есть (SPEC-06). IF у поездки нет дат, THEN даты пусты.
  *Verify: unit.*
- **AC-12.** The system **shall** оформить «Номер брони», значения дат и времён и код валюты как «билетные» данные моно (список AGENTS.md); телефон,
  суммы и залог, компанию, места, адрес, класс, заметки — Manrope, не моно. *Verify: unit.*
- **AC-13.** The system **shall not** хранить таймзону аренды: у аренды нет момента времени, только местные дата и время
  офиса (урок отеля, `mobile/insights.md`, 2026-09-24), а у поездок `country`/`custom` `trips.iana_timezone` пуст, так что
  «снимок таймзоны поездки» блокировал бы аренду в них. Таймзона нужна только предупреждению AC-37 и берётся из вылета
  рейса. Правило AGENTS.md «время — UTC + IANA» этим уточняется для аренды (как для отеля). *Verify: unit.*
- **AC-14.** WHEN пользователь раскрывает «Ещё», the system **shall** повернуть шеврон на 180° и показать три поля; IF
  при открытии правки в «Ещё» есть заполненное значение (доп. водитель включён, залог или заметки не пусты), THEN
  блок раскрыт сразу. *Verify: unit.*

### Даты (шторка «Даты аренды»)
- **AC-15.** The system **shall** показывать даты ОДНИМ полем «Даты» (значение моно, иконка календаря справа), формат:
  «19 – 27 авг 2026»; разные месяцы «30 авг – 2 сент 2026»; разные годы «30 дек 2026 – 3 янв 2027» (локализуется через
  i18n/`Intl`, en — свои сокращения). Пустое поле — плейсхолдер. *Verify: unit (ru + en + uk, все три формата).*
- **AC-16.** WHEN пользователь тапает поле «Даты», the system **shall** открыть нижнюю шторку «Даты аренды» поверх формы:
  подложка `scrim` (fade), панель снизу (slide) токенами `motion.sheetEnter`/`sheetExit` и `easing.enter`, тем же
  in-tree механизмом, что шторка валюты отеля (SPEC-05 AC-62/AC-64); при «Уменьшить движение» — без анимации; фон
  скрыт от скринридера; свайп вниз и тап по подложке закрывают без изменений. Панель: ручка, заголовок «Даты
  аренды», подсказка «Выберите день получения» → «Теперь день возврата» → выбранный диапазон; навигация месяца
  (стрелки 44×44, «Август 2026»), сетка 7 колонок с понедельника, ячейка 44, кружок 40. *Verify: unit + manual.*
- **AC-17.** The system **shall** реализовать выбор диапазона так: первый тап — начало (конец сбрасывается), второй —
  конец; тап раньше начала переносит начало; тот же день — аренда на один день; начало/конец — `accent`/`onAccent`,
  между ними полоса `surfaceStrong`. Логика диапазона — общая с формой поездки/отеля, если она уже вынесена; иначе
  чистая функция в `shared/`, а не копия в клиенте. *Verify: shared/unit.*
- **AC-18.** The system **shall** держать «Готово» шторки неактивной, пока не выбраны обе даты; «Готово» записывает
  диапазон и закрывает шторку. Шторка открывается на месяце начала. *Verify: unit.*
- **AC-19.** WHEN аренда создаётся, the system **shall** отключить дни раньше сегодняшнего (`useToday`), не давать листать
  в месяцы целиком раньше текущего и не пропускать в payload дату получения из прошлого (ошибка
  `car.form.validation.pickup.inPast`, только mobile). WHEN правится аренда с датами в прошлом, the system **shall**
  оставить их сохраняемыми: нижняя граница = min(сегодня, сохранённое получение). *Verify: unit.*

### Время, валидация
- **AC-20.** The system **shall** брать «Время получения» и «Время возврата» из `platform/datePicker` в поведении
  AC-65 SPEC-05 (пустое поле — кнопка, первый тап открывает шторку/диалог, значение пишется только по «Готово»,
  отмена оставляет поле пустым; пустое колесо стоит на 11:00 для обоих полей), значения моно там, где платформа
  позволяет. Оба времени обязательны, поэтому «×» (очистки) нет. *Verify: unit.*
- **AC-21.** The system **shall** требовать: Номер брони, Место получения, обе даты, оба времени; Место возврата — только
  при выключенном «Возврат там же». Все ошибки показываются сразу под полями (`danger`) после первой попытки
  сохранить или ухода из поля. Пустая форма даёт ошибки: номер, место получения, даты, время получения, время возврата.
  *Verify: shared (схема) + unit.*
- **AC-22.** IF возврат (дата+время) не позже получения, THEN the system **shall** показать ошибку под «Время возврата»
  (`danger`) и заблокировать сохранение; при разных датах порядок времён не проверяется. `stayTooLong` (>365 суток)
  показывается под «Даты». *Verify: shared + unit.*
- **AC-23.** The system **shall** ограничить длины полей значениями «Модели данных», считать в code points, trim-ить
  значения; пустая строка после trim у необязательного поля сохраняется как `null`, у обязательного — ошибка.
  *Verify: shared.*
- **AC-24.** WHEN «Возврат там же» включён, the system **shall** писать `return_same_place = true`, `return_place = null`
  (введённое ранее место возврата при этом не отправляется, но в форме сохраняется до закрытия); WHEN выключен —
  показать многострочное поле «Место возврата» и требовать его. *Verify: unit.*

### Ссылка на карты и телефон
- **AC-25.** The system **shall** принимать «Ссылка на карты» и вести себя ровно как у отеля (SPEC-05 AC-24…AC-28):
  `parseMapsUrl` из `shared/`, поле вставки → строка «Ссылка добавлена / Google Maps» + «Открыть» + «×» («Убрать
  ссылку», ≥44pt), повторная проверка перед `Linking.openURL`, ошибка в форме, ссылка не попадает в логи и ошибки,
  сетевых запросов нет. Компонент/логика переиспользуются с отелем, не копируются. *Verify: unit + guardrails.*
- **AC-26.** The system **shall** принимать «Телефон» как текст до 32 символов; после удаления пробелов, `-`, `(`, `)` должен остаться необязательный ведущий `+` и
  3…15 цифр (иначе `tel:` набирал бы мусор); клавиатура `tel`; иначе ошибка «Неверный телефон», пустое — `null`. Проверка — чистая
  функция в `shared/`. *Verify: shared + unit.*

### Стоимость, залог, валюта
- **AC-27.** The system **shall** принимать «Стоимость» и «Залог на карте» по правилам денежного поля отеля
  (SPEC-05 AC-61/AC-63/AC-67: символы цены, ≤2 знаков, `MONEY_MAX_INTEGER_DIGITS`, отброшенный символ не виден) и
  `parseMoneyAmount`; общий компонент поля, не копия. *Verify: unit.*
- **AC-28.** The system **shall** выбирать валюту общей шторкой с отелем (`components/picker/CurrencyPickerSheet`,
  SPEC-06 AC-40/AC-41: поиск, «Не указано», плейсхолдер — домашняя валюта, иначе `EUR`; ссылки на SPEC-05
  AC-55/AC-68 заменены ими), ряд «Стоимость + валюта» 1fr / 112. Валюта обязательна, если заполнена стоимость ИЛИ залог
  (`cost.currencyMissing` под полем валюты). Валюта без стоимости и залога — НЕ ошибка: запись сохраняется без валюты
  (правило SPEC-06 AC-39, одинаково для профильной и выбранной вручную валюты; Q3). Подпись залога — «Залог на карте ·
  EUR» при выбранной валюте, без кода — «Залог на карте». Домашняя валюта — только умолчание при создании (AC-11),
  конвертации нет.
  *Verify: shared + unit.*

### Сохранение, правка, удаление
- **AC-29.** WHEN пользователь нажимает «Сохранить» на валидной форме, the system **shall** создать аренду, закрыть
  форму и показать карточку на S7 без ручного обновления (инвалидация запроса). *Verify: unit.*
- **AC-30.** WHEN открыта правка S16b, the system **shall** показать сохранённые значения как есть (даты и времена местные,

### Предупреждение «возврат позже обратного рейса»
- **AC-37.** The system **shall** считать в `shared/` чистую функцию `carReturnAfterFlight(car, segments)`: момент
  возврата = `return_date` + `return_time` в таймзоне места вылета ближайшего по времени рейса (`mode = flight`),
  вылетающего после получения (`segments/time.ts`, DST-safe), сравнивается с его `departure_at` (UTC); предупреждение —
  когда возврат строго позже. Так две аренды в одной поездке (по одной на город) не дают ложного «нет предупреждения».
  IF подходящего рейса нет, THEN предупреждения нет. Клиент сам не сравнивает. *Verify: shared (пары зон, DST, без
  рейсов, равные моменты, несколько рейсов).*
- **AC-38.** WHEN функция из AC-37 вернула true при текущих значениях формы, the system **shall** показать плашку
  `warnBg`/`warnBorder` под полями времён («Вернуть авто нужно до вылета рейса …» — текст из i18n со временем вылета);
  плашка не блокирует сохранение, пропадает при исправлении. Рейсы берутся из уже загруженного запроса сегментов
  поездки; дополнительных запросов и ошибок при их недоступности нет (плашка просто не показывается).

## Edge cases
- Получение и возврат в один день (аренда на день): валидно; возврат должен быть позже по времени (AC-22).
- Возврат в 05:00 на следующее утро после позднего получения — обычный кейс (ваучер Centauro: 11:00 → 05:00 через 8 суток).
- Поездка без дат: даты пусты; аренда сохраняется только после выбора диапазона.
- Даты аренды вне дат поездки: **не** ошибка (как у отеля).
- Пользователь выключает «Возврат там же» после ввода места, потом включает снова: место возврата не отправляется.
- Валюта выбрана (вручную или из профиля), стоимость и залог пусты: сохраняется без валюты, ошибки нет (SPEC-06 AC-39);
  схема формы обнуляет валюту, БД запрещает валюту без суммы и залога.
- Телефон с добавочным/буквами («+351 308 810 777 ext 2»): ошибка «Неверный телефон», не обрезка молча.
- Очень длинные места/адрес/заметки: лимит с понятной ошибкой.
- Двойной «Сохранить»: один запрос. Удаление уже удалённой аренды на другом устройстве: «Аренда не найдена».
- Открытие S17 по устаревшему id после удаления: то же состояние; `carId` чужой поездки при другом `tripId` в маршруте — тоже «Аренда не найдена».
- Смена аккаунта: кэш аренд очищает `QueryCacheGuard`.
- Копирование при недоступном буфере: ошибка на экране, состояние кнопки не меняется.
