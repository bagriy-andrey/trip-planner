## Проблема и зачем

SPEC-04 сделал настоящим блок «Транспорт». Блок «Отель» на S7 при этом остаётся пунктирной рамкой,
а `/trips/[tripId]/hotels/new` — заглушкой из пяти неинтерактивных текстовых полей
(`booking-form/fields.ts`, вариант `hotel`): ничего не валидируется и не сохраняется.

Ценность отеля в «кошельке бронирований» — то, что нужно на ресепшене: название, точное время
заезда и выезда, адрес, ссылка на карту, номер брони, что включено (завтраки, парковка). Плюс
ночи, которые считаются сами из дат.

Макет формы (скриншот владельца, 2026-09-23) **расходится** с `design/screens/add-hotel.md`:
в макете есть «Ссылка на карты», «Гостей» и «Парковка», а в документе их нет — там даже написано
«карты — чего здесь нет». Порядок вариантов завтрака тоже другой, а «Готово» в шапке
противоречит `add-flight.md`. Этот спек фиксирует итог решений владельца, а `add-hotel.md`
обновляется под него (раздел «Документы дизайна»).

## Goals / Non-goals

**Goals**
1. Отели хранятся в таблице `trip_hotels` с RLS через поездку (тот же приём, что у `trip_segments`).
2. Полный CRUD одного отеля: создание, открытие на правку, сохранение правки, удаление
   с подтверждением. В поездке может быть несколько отелей.
3. Форма отеля целиком заполняется руками, без сети, кроме самого сохранения.
4. Число ночей и допустимый диапазон «дней с завтраком» считаются в `shared/` из календарных дат
   заезда и выезда **в таймзоне места**, одинаково на любом клиенте.
5. ~~Заезд и выезд — момент в UTC плюс IANA-таймзона места.~~ **Заменено (2026-09-24):** заезд и выезд — календарные
   даты места (обязательные) плюс необязательные местные времена; таймзона отеля остаётся полем записи, но моментов в UTC нет.
6. Блок «Отель» на S7 показывает карточки отелей; пустое состояние остаётся, пока отелей нет.
7. Стоимость — число + валюта **на уровне записи**; сумма и валюта заполняются вместе или никак.
8. «Ссылка на карты» — только Google Maps, `https`, из белого списка хостов; открывается системно,
   ни одного сетевого вызова ради ссылки.

**Non-goals** (сознательно НЕ делаем)
- Поиск отелей, подтягивание данных из Booking, карта/превью карты, раскрытие коротких ссылок
  (это сеть; запрещено «Чего не делать в первой фазе» и non-goal SPEC-04).
- Конвертация валют, итоги по поездке, любые денежные хелперы сверх хранения и показа суммы.
- Проверки конфликтов «прилёт — заезд», «отель вне дат поездки», нахлёст двух отелей
  (отдельный будущий спек; данные для них здесь появляются).
- Импорт (`source` пишется только `manual`; значения `imported_*` допустимы схемой, но клиентом
  этой фазы не выставляются).
- Фото, документы, вложения, шаринг, Apple Wallet.
- Автовыбор часов заезда по названию отеля.
- Аренда авто: остаётся заглушкой как есть.

## User stories
- **US-1.** Я открываю поездку, жму «+» у блока «Отель», вставляю ссылку на Google Maps, ввожу
  название — и заезд/выезд уже предзаполнены датами поездки, ночи считаются сами.
- **US-2.** На ресепшене я открываю карточку отеля и сразу вижу время заезда, номер брони и адрес.
- **US-3.** В поездке два города — я добавляю два отеля, каждый со своими датами и таймзоной.
- **US-4.** Я ошибся датой, открываю отель на правку, меняю выезд, ночи пересчитываются.
- **US-5.** Я отменил бронь и удаляю отель; приложение просит подтверждение.

## Модель данных (контракт, не SQL)

Одна новая таблица `trip_hotels`. Точный DDL — дело Implementation Plan.

| Поле | Смысл | Обязательность |
|---|---|---|
| `id` | UUID, генерируется сервером | PK |
| `trip_id` | Поездка-владелец, FK `trips` `ON DELETE CASCADE`; через него выводится владение | not null |
| `source` | `manual` \| `imported_pending` \| `imported_confirmed`, по умолчанию `manual` | not null |
| `name` | Название, 1…120 символов после trim, не пустое | not null |
| `city_place_id` | Идентификатор города из справочника мест (как `trips.place_id`) | not null |
| `time_zone` | IANA-таймзона места, снимок из справочника на момент сохранения; одна на заезд и выезд | not null |
| `address` | Свободный текст, многострочный, до 300 символов | nullable |
| `maps_url` | Ссылка Google Maps, нормализованная, до 2048 символов | nullable |
| ~~`check_in_at` / `check_out_at`~~ | ~~Моменты в UTC~~ — **удалены поправкой 2026-09-24** | — |
| `check_in_date` / `check_out_date` | Календарные даты места (`date`) | not null |
| `check_in_time` / `check_out_time` | Местное время на стене отеля (`time`), необязательное | nullable |
| `guests` | 1…9 (по умолчанию 1) | not null |
| `parking` | `none` \| `free` \| `paid`, по умолчанию `none` | not null |
| `breakfast` | `all` \| `partial` \| `none`, по умолчанию `none` | not null |
| `breakfast_days` | Дней с завтраком; только при `breakfast = partial` | nullable |
| `cost_amount` | Неотрицательное число, до 2 знаков после запятой, до 12 цифр | nullable |
| `cost_currency` | Код ISO 4217, 3 заглавные буквы | nullable |
| `booking_ref` | Номер брони, до 32 символов, без пробелов по краям | nullable |
| `notes` | «Удобства и требования», до 1000 символов | nullable |
| `created_at` / `updated_at` | Служебные; `updated_at` — триггер `set_updated_at` | not null |

Инварианты: ~~`check_out_at > check_in_at`~~ → `check_out_date >= check_in_date`, `check_out_date - check_in_date <= 365`,
при равных датах и обоих временах `check_out_time > check_in_time`; `cost_amount` и `cost_currency` — оба или ни одного;
`breakfast_days is not null` ⇔ `breakfast = 'partial'`; `breakfast_days` ≥ 1.

## Acceptance criteria (EARS)

### Хранение, владение и RLS
- **AC-1.** The system **shall** хранить отели в `trip_hotels`, созданной миграцией
  `supabase/migrations/`; правки через дашборд не считаются реализацией.
  *Verify: manual (`supabase db reset` локально) + db.*
- **AC-2.** The system **shall** держать RLS на `trip_hotels` с политиками `select/insert/update/delete`,
  допускающими строку только когда её `trip_id` указывает на поездку текущего пользователя;
  колонки-владельца нет; `update` проверяет ownership и в `using`, и в `with check`.
  *Verify: db (pgTAP: владелец / другой пользователь / anon на каждую операцию).*
- **AC-3.** IF пользователь читает, меняет или удаляет отель чужой поездки, THEN the system **shall**
  вести себя так, будто строки нет (0 строк, без утечки данных).
  *Verify: db.*
- **AC-4.** IF вставка идёт с `trip_id` чужой или несуществующей поездки, ИЛИ update переносит отель
  в чужую поездку, THEN the system **shall** отклонить операцию.
  *Verify: db.*
- **AC-5.** WHEN удаляется поездка или пользователь, the system **shall** удалить её отели каскадом.
  *Verify: db.*
- **AC-6.** The system **shall** проверять инварианты на уровне БД CHECK-ограничениями: формат
  и длины полей, `check_out_at > check_in_at`, значения `source`/`parking`/`breakfast`,
  пары `cost_*` и связь `breakfast_days` с `partial`, формат валюты и IANA-таймзоны, гости 1…9.
  *Verify: db (по одному падающему insert на каждое ограничение).*
- **AC-7.** The system **shall** регенерировать `shared/src/db/database.types.ts` после миграции.
  *Verify: manual + typecheck.*

### Форма: поля и предзаполнение
- **AC-8.** **[Заменён поправкой 2026-09-24, см. AC-50…AC-58]** The system **shall** показывать поля в порядке макета: Название, Город, Адрес,
  Ссылка на карты, Заезд (дата + время), Выезд (дата + время), строка «N ночей — считается
  из дат», Гостей, Парковка, Завтраки, Дней с завтраком (только при «Частично»),
  Стоимость + валюта, Номер брони, Удобства и требования.
  *Verify: unit (RNTL) + manual против скриншота.*
- **AC-9.** The system **shall** оформить форму как формы SPEC-04: шапка с крестиком (голосом
  «Отмена»), заголовком «Отель» и **без** «Готово»; основная кнопка «Сохранить» в нижней панели;
  «Сохранить и добавить следующий» нет.
  *Verify: unit.*
- **AC-10.** (частично заменён: даты — одним диапазоном, AC-50) WHEN форма открыта на создание, the system **shall** предзаполнить «Город» городом
  поездки, если он из справочника мест, а заезд и выезд — датой начала и датой окончания поездки;
  время остаётся пустым, пока пользователь его не выберет.
  *Verify: unit.*
- **AC-11.** IF у поездки нет дат, THEN the system **shall** оставить даты пустыми и не показывать
  строку ночей. IF у поездки нет города из справочника, THEN «Город» пуст и обязателен.
  *Verify: unit.*
- **AC-12.** The system **shall** брать таймзону отеля из справочника по выбранному городу; в форме
  таймзона не вводится и не показывается. «Город» принимает только выбор из подсказок
  справочника (ошибка «Выберите город из списка», как у аэропортов в SPEC-04).
  *Verify: unit + shared.*
- **AC-13.** **[Заменён поправкой 2026-09-24, см. AC-50…AC-58]** The system **shall** использовать пикеры даты и времени из `platform/datePicker`
  в стиле SPEC-04: один тап по пустому полю открывает пикер, значение появляется после выбора,
  у заполненного поля справа крестик «Очистить», время открывается на 15:00 (заезд) и 11:00 (выезд),
  дата выезда не может быть раньше даты заезда в календаре.
  *Verify: unit + manual.*
- **AC-14.** The system **shall** оформить значения дат, времени и «Номера брони» моно-шрифтом,
  название, город, адрес и число гостей — Manrope, не моно.
  *Verify: unit.*

### Валидация
- **AC-15.** **[Заменён поправкой 2026-09-24, см. AC-50…AC-58]** The system **shall** требовать «Название», «Город», обе даты и оба времени; пустое
  обязательное поле подсвечивается `danger` с текстом ошибки под полем после первой попытки
  сохранить или ухода из поля; все ошибки формы показываются сразу (без «одна за раз»).
  *Verify: shared (схема) + unit.*
- **AC-16.** **[Заменён поправкой 2026-09-24, см. AC-50…AC-58]** IF выезд не позже заезда (сравнение по UTC-моментам), THEN the system **shall** показать
  ошибку под полем «Выезд» цветом `danger` и заблокировать сохранение.
  *Verify: shared + unit.*
- **AC-17.** The system **shall** ограничить длины полей значениями «Модели данных» и считать длину
  в code points; поля trim-ятся, пустая строка после trim сохраняется как `null`.
  *Verify: shared.*
- **AC-18.** The system **shall** ограничить срок проживания 365 ночами.
  *Verify: shared.*
- **AC-19.** (часть про ввод валюты заменена: выбор из шторки, AC-55) The system **shall** принимать «Стоимость» как неотрицательное число не более чем с 2
  знаками после запятой (разделитель `.` или `,`), и валюту из закрытого списка кодов ISO 4217
  в `shared/`; сумма без валюты и валюта без суммы — ошибка соответствующего поля. Валюта
  по умолчанию не предзаполняется и не берётся из профиля (валюта на уровне записи).
  *Verify: shared + unit.*

### Ночи и завтраки (`shared/`)
- **AC-20.** (уточнён: только календарные даты, таймзона в расчёте не участвует) The system **shall** считать ночи в `shared/` как разность календарных дат заезда
  и выезда в таймзоне отеля (не разность моментов), одной чистой функцией, устойчивой к DST.
  The mobile client **shall not** пересчитывать ночи сам.
  *Verify: shared (граничные случаи: DST, 23/25-часовые сутки, разные пояса, 0 ночей).*
- **AC-21.** The system **shall** показывать «N ночей — считается из дат» (склонение ru/en через
  i18next plural) под датами, обновлять при смене любой даты и скрывать строку, пока нет обеих
  дат или пока ночей 0.
  *Verify: unit.*
- **AC-22.** WHEN выбран «Частично», the system **shall** показать степпер «Дней с завтраком»
  со значением по умолчанию 1 и диапазоном 1…max(1, ночей − 1); IF ночей неизвестно, THEN 1…30.
  WHEN выбран «Все дни» или «Нет», степпер скрыт и `breakfast_days` пишется `null`.
  *Verify: shared + unit.*
- **AC-23.** WHEN даты меняются так, что сохранённое «дней с завтраком» выходит за диапазон, the system
  **shall** привести его к границе диапазона, а не оставить невалидным.
  *Verify: unit.*

### Ссылка на карты
- **AC-24.** The system **shall** принимать в «Ссылка на карты» только URL со схемой `https`
  и хостом из белого списка: `www.google.com`/`google.com` с путём `/maps…`, `maps.google.com`,
  `maps.app.goo.gl`, `goo.gl` с путём `/maps…`; всё остальное (другая схема, `javascript:`,
  `http`, хост-двойник вроде `google.com.evil.tld`, креды в URL) — ошибка «Нужна ссылка Google Maps».
  Проверка — чистая функция в `shared/`, одна на все клиенты.
  *Verify: shared (таблица допустимых и недопустимых, включая обходы через userinfo, порт, регистр
  хоста, пробелы, юникод-двойники).*
- **AC-25.** The system **shall** хранить нормализованную ссылку (trim, схема и хост в нижнем регистре)
  до 2048 символов и не делать ни одного сетевого запроса ради неё.
  *Verify: unit + guardrail `no-backend-or-network`.*
- **AC-26.** WHEN ссылка добавлена, the system **shall** показать строку «Ссылка добавлена /
  Google Maps», кнопку «Открыть» и кнопку «×» (очистить, зона нажатия ≥44pt, голосом «Убрать
  ссылку»); WHEN ссылки нет, — поле ввода/вставки.
  *Verify: unit.*
- **AC-27.** WHEN пользователь нажимает «Открыть», the system **shall** повторно проверить ссылку
  функцией из AC-24 и открыть её через `Linking.openURL`; IF проверка не прошла или система не смогла
  открыть, THEN показать ошибку в форме, а не системный алерт.
  *Verify: unit.*
- **AC-28.** The system **shall not** писать `maps_url`, адрес, номер брони и заметки в логи и в
  тексты ошибок (guardrail `no-credentials-in-logs`).
  *Verify: guardrail.*

### Сохранение, правка, удаление
- **AC-29.** WHEN пользователь нажимает «Сохранить» на валидной форме, the system **shall** создать
  отель, закрыть форму и показать карточку на S7 без ручного обновления (инвалидация запроса).
  *Verify: unit.*
- **AC-30.** **[Заменён поправкой 2026-09-24, см. AC-50…AC-58]** (UTC-моментов больше нет; `check_in_at`/`check_out_at` удалены) The system **shall** собирать `check_in_at`/`check_out_at` из даты, времени и таймзоны
  отеля функцией в `shared/` (переиспользовать `segments/time.ts`; DST-safe для обоих знаков смещения).
  *Verify: shared (пары зон New_York и Warsaw, gap и overlap).*
- **AC-31.** (уточнён: даты и времена показываются как сохранены, без пересчёта зон) WHEN открыта правка существующего отеля, the system **shall** показать сохранённые
  значения в таймзоне отеля, а не устройства; «Сохранить» остаётся активной.
  *Verify: unit (устройство и отель в разных зонах).*
- **AC-32.** WHEN пользователь удаляет отель на S14b, the system **shall** запросить подтверждение
  (in-tree overlay, не системный `Alert`), после подтверждения удалить запись, вернуться на S7 и убрать
  карточку.
  *Verify: unit.*
- **AC-33.** IF `hotelId` неизвестен, чужой или не UUID, THEN the system **shall** показать одно
  состояние «Отель не найден» с возвратом назад, без падения и без утечки чужих данных.
  *Verify: unit + db.*
- **AC-34.** The system **shall** сохранять `source = 'manual'` при создании из клиента и не давать
  пользователю его менять.
  *Verify: unit + api.*

### Блок «Отель» на S7
- **AC-35.** (уточнён AC-56/AC-57: сортировка по дате и времени заезда, время только если задано) WHEN у поездки есть отели, the system **shall** показать в блоке «Отель» карточки,
  отсортированные по `check_in_at`: название, шеврон, ниже заезд и выезд (моно, в таймзоне отеля),
  ниже чип завтраков («Завтраки: все дни / частично, N дн. / нет» — при «Нет» чип не показывается).
  *Verify: unit.*
- **AC-36.** WHEN отелей нет, the system **shall** показывать существующее пустое состояние
  с кнопкой «Добавить отель»; при наличии отелей кнопка «Добавить отель» остаётся в шапке блока

  *Verify: unit.*

## Edge cases
- Поездка без дат: даты пусты, ночей нет, «Частично» даёт 1…30.
- Заезд и выезд в один день (day-use): валидно; если заданы ОБА времени, выезд должен быть позже; ночей 0,
  строка ночей скрыта.
- Даты отеля вне дат поездки: **не** ошибка и не предупреждение в этом спеке.
- Устройство в одной таймзоне, отель в другой: даты и времена показываются как сохранены (местные для отеля, без пересчёта).
- ~~Заезд в DST-gap или выезд в DST-overlap~~ — неактуально после поправки 2026-09-24 (нет UTC-моментов).
- Вставка ссылки с хвостовыми пробелами/переводом строки: trim до проверки.
- Короткая ссылка `maps.app.goo.gl/…` не раскрывается и не проверяется по сети — только по хосту.
- Пользователь меняет город после выбора дат: таймзона меняется; даты и времена остаются как введены.
- Пользователь уменьшает даты, а «дней с завтраком» больше ночей − 1: приводится к границе (AC-23).
- Очень длинное название/адрес: лимит с понятной ошибкой, без обрезки молча.
- Двойное нажатие «Сохранить»: один запрос.
- Удаление отеля, уже удалённого с другого устройства: состояние «Отель не найден», не ошибка.
- Смена аккаунта: кэш отелей очищается `QueryCacheGuard`, как остальной.
