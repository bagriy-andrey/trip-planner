# Форма сегмента (рейс)

Добавление и редактирование одного сегмента маршрута. Оболочка экрана общая
для всех форм модулей; поля отеля и авто — в `add-hotel.md` и `add-car.md`.
Цепочка сегментов и правила пауз — в `route.md`.

## Структура

1. Шапка: только «Рейс» по центру — ни крестика, ни «Готово». Форму можно
   закрыть свайпом вниз или кнопкой «Отмена» внизу; при несохранённых
   правках сначала спрашиваем «Закрыть без сохранения?».
2. Прокручиваемое тело формы.
3. Внизу кнопки: основная «Сохранить» (сохраняет и закрывает форму),
   вторичная «Сохранить и добавить следующий» (только при создании) и
   вторичная «Отмена» (закрывает форму; при правках — с подтверждением).
   В режиме правки — «Сохранить» и «Отмена».

Обязательные поля и ошибки валидации подсвечиваются `danger` (в светлой
теме `#B3452F`, контраст ≥4.5:1). Вылет в прошлом и вылет раньше начала
поездки не сохраняются (правка старого рейса без смены даты/времени/аэропорта
вылета разрешена). Номер рейса: подсказка «LO 1234», ошибка формата — после
ухода из поля. Дата вылета — одно поле во всю ширину (значение моно, справа иконка
календаря), тап открывает нижнюю шторку с календарём в том же виде, что
«Даты аренды» (выбор одного дня, «Готово» активна после выбора; день
раньше сегодня и раньше начала поездки выбрать нельзя). Ниже в один ряд
«Вылет» (время, шторка с колесом, открывается на 12:00) и «Длительность»
(необязательно; колесо «часы:минуты» в 24-часовом виде, открывается на
02:00; у заполненного поля справа крестик «Очистить»; 00:00 = очистить).
Значение появляется только после выбора.
Окно «Закрыть без сохранения?» рисуется поверх всего экрана, прижатым
к низу, независимо от прокрутки формы.
При пассажирах >1 поля становятся «Места» и «Номера билетов»
(значения через запятую, по одному на пассажира; до 64 и 160 символов).

## Поля

| Поле | Тип | Замечание |
| --- | --- | --- |
| Номер рейса | текст, моно | первым полем, граница `accent` когда распознан |
| Откуда | текст с подсказками | из офлайн-справочника аэропортов, выбор обязателен |
| Куда | текст с подсказками | то же |
| Дата вылета | дата | значение моно |
| Вылет | время | значение моно |
| Длительность | часы:минуты | необязательно, значение моно, см. «Прилёт из длительности» |
| Багаж включён | переключатель | пилюля 44×24 |
| Пассажиры | счётчик | 1…9, не моно |
| Место | текст, моно | |
| Номер билета | текст, моно | |

Номер рейса: 2 буквы/цифры кода авиакомпании + 1–4 цифры + необязательная
буква (например, `LO 1234`, `AA 100A`); пробелы и дефисы при вводе игнорируются
и приводятся к верхнему регистру. Нераспознанный код — это НЕ ошибка формы,
поле остаётся валидным, просто строка авиакомпании ниже не появляется.

«Откуда» и «Куда» принимают только выбор из подсказок офлайн-справочника
аэропортов — если пользователь напечатал текст, но не выбрал вариант,
поле при сохранении подсвечивается ошибкой «Выберите аэропорт из списка,
можно искать по коду». Одинаковый аэропорт в «Откуда» и «Куда» — отдельная
ошибка поля «Куда».

Под номером рейса — строка с галочкой и названием авиакомпании, распознанной
по коду из встроенного справочника: «LOT Polish Airlines — из справочника,
офлайн». Справочник кодов авиакомпаний статичен и лежит в приложении
рядом со справочником аэропортов.

Под «Вылетом» и «Длительностью» — пояснение, что длительность необязательна и
нужна только для расчёта стыковок.

## Прилёт из длительности

Полей даты и времени прилёта в форме нет. Если указана длительность, прилёт
хранится как вылет + длительность (момент в UTC; дата и время прилёта в
часовом поясе аэропорта назначения считаются из него, схема и расчёт стыковок
не меняются). Без длительности прилёта нет — стыковки для такого рейса не
считаются. При правке длительность показывается как прилёт − вылет; колесо
покрывает до 23:59, более длинные рейсы (до 48 часов по схеме) показываются в
поле как есть, а колесо для них открывается с 00:00.

## Удаление сегмента

Только в режиме правки (сегмент уже сохранён), внизу формы после «Отмена» —
кнопка «Удалить рейс» (та же пилюля, что «Отмена», но рамка и текст `danger`). Деструктивное действие: тап открывает шторку
подтверждения (не системный `Alert`, тот же паттерн, что в `trip-detail.md`)
с текстом, что рейс будет удалён без возможности восстановления, кнопкой
«Удалить рейс» (рамка и текст `danger`, без заливки) и «Отмена». Повторное
нажатие на «Удалить рейс» во время выполнения игнорируется (спиннер на
кнопке); ошибка показывается в той же шторке, подтверждение можно повторить.

## Автозаполнение

В первой версии фичи внешнего API нет. Номер рейса даёт только название
авиакомпании, остальное вводится руками с подсказками аэропортов.

Когда API появится, он встраивается сюда же: по номеру рейса и дате
подставляются города и время. Два требования к той версии — ключ живёт
на сервере в Edge Function, а не в приложении, и форма остаётся полностью
заполняемой руками при любом отказе: нет сети, нет рейса в базе, чартер.

## Предзаполнение

- Город назначения берётся из поездки, дата вылета — из даты её начала.
- Для первого сегмента поездки «Откуда» = домашний аэропорт профиля (если задан),
  «Куда» = аэропорт города поездки (SPEC-06 AC-33/AC-34).
- При добавлении следующего сегмента «Откуда» подставляется из города
  прилёта предыдущего. Это то, что делает ввод мультигорода дешёвым.
- Если предыдущий сегмент был последним и маршрут не замкнут, «Куда»
  подставляется городом начала поездки.

## Поведение

- Кнопка внизу сохраняет сегмент и сразу открывает форму следующего
  с подставленным «Откуда». Для простой поездки это и есть обратный рейс.
- Отдельного чекбокса «туда-обратно» нет: он ломается на мультигороде.
- Закрытие без сохранения спрашивает подтверждение, только если
  что-то изменено.
- Маршрут с id открывает существующий сегмент, а не пустую форму.
