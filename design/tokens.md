# Токены: канонические значения

Единственная тема живёт в приложении (`mobile/src/lib/theme`). Этот файл —
источник правды по значениям и именам. Код обязан ему соответствовать;
расхождение чинится в теме приложения, а не по месту использования.

Если значение меняется, оно сначала меняется здесь, потом в коде.


`coverScrim` — тонкое затемнение поверх цветной обложки под стеклянной
панелью. Без него в светлой теме тёмный текст на стекле поверх акцентной
подложки даёт около 4.8:1, на грани допустимого.

Цвета обложек-плейсхолдеров выбираются детерминированно по **идентификатору
поездки** (не по названию места): идентификатор неизменен и не зависит от языка,
поэтому переименование, смена названия и смена языка цвет не перекрашивают.
Один и тот же цвет у двух поездок в один город не гарантируется — это цена
стабильности.

```ts
coverColors = ['#1F4F4A', '#8C4A34', '#33384F', '#7A4A6B', '#4A5A3A']
```

Индекс считается общей функцией из `shared/` (хэш идентификатора по модулю
длины палитры), одинаковой на всех клиентах; отдельного поля обложки в БД нет.

Пустые состояния и загрузка не вводят новых токенов: пунктирная рамка пустого
блока — это `surfaceBorder` со стилем `dashed` и шириной `layout.borderWidth`,
фон скелетона — `divider`.

## Размеры и отступы

```ts
radius = { tile: 10, field: 14, card: 18, cover: 24, sheet: 26, pill: 999, tabBar: 32 }

// Каркас экрана: боковые поля, промежутки между карточками и блоками
spacing = { screenX: 20, gap: 12, block: 20, section: 24 }

// Внутренние отступы компонентов — существующая шкала приложения
scale = { xs: 4, sm: 8, md: 12, lg: 16, xl: 24, xxl: 32 }
```

Две группы намеренно разные и сводить их в одну не нужно. Значение 20
в шкалу `scale` не ложится, а сдвиг `xl` с 24 на 20 сломал бы шесть десятков
мест использования. `spacing` отвечает за каркас экрана, `scale` — за внутренние
отступы компонентов.

## Состояния

Отключённая кнопка — это фон `divider` и текст `textTertiary`,
а не прозрачность на активном стиле. Прозрачность для disabled не использовать:
она тянет за собой текст и ломает контраст.

Нажатое состояние — прозрачность 0.7 на всём элементе, это допустимо.

## Проверка контраста warnBg / warnBorder / danger (2026-09-22, PLAN-04 шаг 5)

Экран «Маршрут» (`design/screens/route.md`) — первое место, где `warnBg` и
`warnBorder` реально рисуются (чип «рискованно», полый узел паузы, карточка
«маршрут не замкнут»). Перед тем как размеры цепочки ушли в тему, контраст
перепроверен заново в обеих темах (относительная светимость sRGB, формула
WCAG; `warnBg`/`warnBorder` — их alpha-значения поверх `bg`):

- Текст обычного цвета (`text`) на фоне `warnBg` (слово «рискованно», текст
  карточки «не замкнут») — тёмная тема ≈15.5:1, светлая ≈14.7:1. Оба далеко
  выше требуемых 4.5:1, значения не меняются.
- `warnBorder` как графическая граница (полый узел паузы, пунктирная рамка
  карточки) — не текст, а вспомогательный сигнал: рядом всегда есть слово
  («рискованно», «Маршрут не замкнут» — правило AGENTS.md «цвет не должен
  быть единственным носителем смысла»). Замер против `surface`/`bg` даёт
  ≈1.3–1.9:1 в обеих темах — ниже рекомендованных 3:1 для нетекстовых
  элементов (WCAG 1.4.11), но так как это не единственный носитель значения
  «рискованно», сознательно оставлено как есть; будущая раскладка экрана не
  должна полагаться на этот цвет как на единственный сигнал.
- `danger` (уже используется на нескольких экранах — `trip-detail`, `auth`,
  `trip-form`, `account` — как цвет текста ошибок/кнопок, размер `small`,
  то есть нужны полные 4.5:1) как текст на сплошном `bg`: тёмная тема
  ≈5.7:1 — в порядке; светлая тема ≈4.2:1 — **ниже** 4.5:1. Это расхождение
  СУЩЕСТВОВАЛО до этого шага. **Исправлено 2026-09-23:** светлое значение
  `danger` затемнено с `#C0503C` до `#B3452F` — на `bg` ≈4.9:1, на `surface`
  ≈5.2:1 (тёмная тема без изменений, ≈5.7:1). Понадобилось, потому что
  ошибки формы рейса теперь красные (`danger`), а не серые.

## Известные расхождения с текущим кодом

На момент составления в приложении: `onAccent` был `#0B0D11`, светлый
`textSecondary` 0.62 вместо 0.58, `pill` 0.10/0.07 вместо `divider` 0.12/0.10,
радиус карточек 20 вместо 18, блюр 30 вместо 20, боковой отступ 16 вместо 20,
граница `hairlineWidth` вместо 1. Всё это чинится в теме.
